# Checkpoint Thumbnail Exporter Specification

## Project / Node

- Project name: `ComfyUI-CheckpointThumbnailExporter`
- Node display name: `Checkpoint Thumbnail Exporter`
- Internal node class: `CheckpointThumbnailExporter`

`TOOL_BUILD` is a ChatGPT-assisted zip/build label only. It must not be written into generated JPEG comments.

Stable JPEG metadata uses:

```text
comment_schema=cte_comment_v1
```

## Purpose

`Checkpoint Thumbnail Exporter` reuses checkpoint-specific images generated by HandpickerSuite / GM Image Saver as OGN-ModelManager checkpoint thumbnails.

Core story:

```text
Run HandpickerSuite first
↓
Checkpoint-specific images accumulate
↓
Checkpoint Thumbnail Exporter selects the latest image for each checkpoint
↓
Missing OGN-ModelManager thumbnails are installed automatically
```

This node is not a generic one-image copier. It is a post-run batch utility for reusing HandpickerSuite image assets.

It can also serve as a lightweight visual checkpoint catalog: after cycling checkpoints and exporting thumbnails into OGN-ModelManager, users can compare checkpoint results at a glance and feed that judgment back into HandpickerSuite tagging/review workflows.

## GraphicsMagick decision

GraphicsMagick is intentionally not used.

Reason:

- GM Image Saver benefits from GraphicsMagick because it saves images repeatedly during generation.
- Checkpoint Thumbnail Exporter only creates small JPEG thumbnails for missing checkpoint thumbnails.
- Requiring GraphicsMagick would make installation and reporting heavier than necessary.
- Pillow is sufficient for resizing, RGB conversion, EXIF orientation handling, and JPEG comment writing.

## UI design

The node is a standalone utility panel. It does not need inputs or outputs.

Widget order is important for readability:

```text
source_image_root
target_format
max_size
jpeg_quality
operation
run_mode
button
progress
report
```

Rationale:

- `source_image_root` is the source setting.
- `target_format`, `max_size`, and `jpeg_quality` are output-thumbnail settings.
- `operation` and `run_mode` are execution settings.
- The button must appear after all settings and immediately before progress/report.

Widgets:

```text
source_image_root: STRING
  Empty = current ComfyUI output folder.

target_format:
  OGN-ModelManager

max_size:
  default 512

jpeg_quality:
  default 90

operation:
  install_missing
  uninstall_managed

run_mode:
  dry_run
  execute
```

Button labels:

```text
install_missing + dry_run  -> 🎨 [Dry Run] Find Missing Thumbnails
install_missing + execute  -> 🎨 [Execute!] Install Missing Thumbnails
uninstall_managed + dry_run -> ❌ [Dry Run] Find Managed Thumbnails
uninstall_managed + execute -> ❌ [Execute!] Uninstall Managed Thumbnails
```

Button icons are always shown because the button expresses the selected operation target.

Report first-line icons are stricter:

```text
Dry run complete.
🎨 Install complete.
❌ Uninstall complete.
```

Dry run reports do not use operation icons because no file-changing operation occurred.
Execute reports use the icon only if the corresponding action actually changed files:

- `🎨 Install complete.` only when one or more thumbnails were written.
- `❌ Uninstall complete.` only when one or more managed thumbnails were removed.

Initial Ready report text is fixed and should remain compact:

```text
Ready.

Button behavior = operation + run_mode.

🎨 install_missing
  dry_run : find missing thumbnails
  execute : install missing thumbnails

❌ uninstall_managed
  dry_run : find managed thumbnails
  execute : uninstall managed thumbnails

dry_run changes nothing.
Empty source_image_root uses ComfyUI output.
```

Do not add long next-step guidance to every dry-run result. The initial Ready message already explains the safe workflow, and long dry-run footers make the report area noisy.

## Long-scan progress behavior

When `install_missing` must scan many source images, the UI should not look frozen.

Rules:

- During source image scanning, emit a progress heartbeat every 100 source image files.
- Each heartbeat adds one `.` character to the live report.
- The live report shows:
  - `Scanned`: number of source image files inspected
  - `Hit images`: source images that matched at least one checkpoint candidate
  - `Matched checkpoints`: checkpoint count that has at least one selected source image candidate
  - `Ambiguous images`: source images skipped because they matched multiple checkpoints at the same best rank
- Do not show the hit/ambiguous counters in the narrow progress line because they overlap with normal path display.
- During `scanning_source`, the progress line should not draw `current_name`.
- The top blue bar may remain phase-based during scanning because total source-image count is not precomputed.

Constants:

```python
SCAN_PROGRESS_DOT_EVERY_FILES = 100
SCAN_PROGRESS_MAX_DOTS = 120
MAX_SCAN_SOURCE_IMAGES = 5000
```

Rationale:

- Counting all source files up front would require an extra full scan.
- A simple dot heartbeat keeps the node responsive and makes long unmatched scans understandable.
- The text labels avoid confusion between source-image hits and matched-checkpoint count.
- The scan limit prevents very broad source roots from turning into an unexpectedly long operation.
- The scan limit is shown only if reached, because showing it during normal progress can be mistaken for total file count.

## Safety UI rules

- Changing `operation` resets `run_mode` to `dry_run`.
- After any `execute` run completes, `run_mode` is reset to `dry_run`.
- `uninstall_managed + execute` requires a fresh `uninstall_managed + dry_run` confirmation token.
- The confirmation token expires after 10 minutes.
- If uninstall confirmation is missing or expired, no files are removed.

## source_image_root behavior

```text
source_image_root = ""
  -> folder_paths.get_output_directory()
```

Important troubleshooting note:

If all checkpoints become unmatched, check `source_image_root` first.

A common trap is that GM Image Saver may save to an explicit output directory while this node, with an empty `source_image_root`, uses the current ComfyUI output directory. Also, update tools may recreate a junction/symlinked `output` folder as a normal folder.

## OGN-ModelManager integration boundary

This node does not call OGN-ModelManager APIs and does not modify OGN-ModelManager internal state or cache.

It only creates files in the layout OGN-ModelManager already supports:

```text
models/checkpoints/foo.safetensors
models/checkpoints/foo.jpg
```

For subfolders:

```text
models/checkpoints/subdir/foo.safetensors
models/checkpoints/subdir/foo.jpg
```

If thumbnails do not appear immediately, the user should reload OGN-ModelManager or restart ComfyUI.

## install_missing algorithm

Important rule: check target thumbnails first.

```text
1. Get ComfyUI checkpoint list.
2. For each checkpoint, check whether an OGN-compatible sidecar thumbnail already exists.
3. If every checkpoint already has a thumbnail, do not scan source_image_root.
4. Only for missing thumbnails, scan source_image_root.
5. Find the latest source image for each missing checkpoint.
6. dry_run: report what would be installed.
7. execute: write resized .jpg thumbnail next to the checkpoint file.
```

Existing sidecar thumbnail detection:

- same stem as checkpoint
- same directory as checkpoint
- extension case-insensitive
- recognized OGN-style sidecar extensions:

```text
.jpg
.jpeg
.png
.webp
.gif
.svg
```

Output format:

- `.jpg` only
- shrink only
- keep aspect ratio
- max side = `max_size`
- quality = `jpeg_quality`

## Source image matching

For each checkpoint, source keys are generated from:

1. checkpoint relative path without extension, sanitized
2. checkpoint basename stem, sanitized
3. checkpoint basename stem as-is

Examples:

```text
foo.safetensors -> foo
illustrious/foo.safetensors -> illustrious_foo, foo
```

`source_image_root` is scanned once, and only if at least one checkpoint is missing a thumbnail.

Source image matching supports substring matching against the checkpoint-safe key because HandpickerSuite / GM Image Saver output layouts vary:

```text
source_image_root/<ckpt_name_safe>/image_0001.jpg
source_image_root/prefix/date/<ckpt_name_safe>/image_0001.jpg
source_image_root/prefix_<ckpt_name_safe>_20260611_0001.jpg
source_image_root/prefix/date/prefix_<ckpt_name_safe>_0001.jpg
```

Match priority:

```text
0. exact normalized parent directory segment match
1. normalized parent directory segment contains ckpt_name_safe
2. normalized filename stem contains ckpt_name_safe
3. normalized relative path contains ckpt_name_safe
```

If one source image matches multiple checkpoints at the same best priority, it is skipped as ambiguous. If several images match the same checkpoint, the latest image wins.

Representative rule is fixed:

```text
latest
```

Latest means highest file modification time, with filename as tie-breaker.

## JPEG comment

Generated JPEG thumbnails include management metadata in the JPEG comment.

Example:

```text
Checkpoint Thumbnail Exporter
managed=true
tool=Checkpoint Thumbnail Exporter
comment_schema=cte_comment_v1
target=OGN-ModelManager
checkpoint=waiNSFWIllustrious_v150.safetensors
source_dir=waiNSFWIllustrious_v150
source_file=waiNSFWIllustrious_v150/image_0008.jpg
representative_rule=latest
created_at=2026-06-11T01:23:45+0900
```

Do not include `TOOL_BUILD` or temporary zip labels in JPEG comments.

Tag/favorite metadata is intentionally not included in 0.1.0. It can be added later only if users ask for tag overlays or thumbnail style refresh.

## uninstall_managed algorithm

```text
1. Get ComfyUI checkpoint list.
2. Find sidecar thumbnails next to each checkpoint.
3. For `.jpg` / `.jpeg`, read JPEG comment.
4. If it contains this node's management marker, it is managed.
5. dry_run: report managed thumbnails.
6. execute: remove managed thumbnails only.
```

Manual thumbnails, OGN-uploaded thumbnails, and unmanaged sidecar images are skipped.

## HandpickerSuite deletion-script relation

This exporter only uninstalls thumbnails that it manages.

A separate HandpickerSuite checkpoint deletion script may delete same-stem sidecar thumbnails when the checkpoint itself is intentionally deleted. In that deletion-script context, JPEG comment checks are unnecessary because the checkpoint is being removed, so same-stem sidecar thumbnail cleanup is expected.

Recommended deletion-script sidecar cleanup:

- delete same-stem image sidecars
- extension comparison case-insensitive
- do not delete `.txt` memo files by default

## Refresh managed thumbnails

There is intentionally no separate `refresh_managed` operation in 0.1.0.

To refresh thumbnails managed by this node:

```text
1. uninstall_managed
2. install_missing
```

This keeps the operation set small and preserves the rule that manual/unmanaged thumbnails are not touched.

## Current limitations

- OGN-ModelManager only
- `.jpg` output only
- representative rule fixed to `latest`
- no overwrite mode
- no Civitai download
- no tag/favorite overlay burn-in
- no `.txt` memo generation
- no GraphicsMagick backend

## Implementation notes for future zip generation

- Keep specs under `.spec/*.md`, not as `*.spec` files.
- Update this spec when UI or behavior changes.
- Do not write temporary build labels into JPEG comments.
- Preserve the OGN integration boundary: file placement only, no OGN API/cache mutation.
- Preserve the target-first optimization: do not scan `source_image_root` if no thumbnails are missing.
- Preserve the one-button utility-panel design.
- If `operation` changes, reset `run_mode` to `dry_run`.
- If `execute` finishes, reset `run_mode` to `dry_run`.
- Button icons are always shown; report icons are shown only for actual file-changing actions.
